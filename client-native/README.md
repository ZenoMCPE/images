# Internal client native builders

Application source stays in private `ZenoMCPE/client`. This public infrastructure
repository contains the trusted native build workflow and helpers, with no
application source history. Completed release packages are published separately
to the project download server by the private pipeline. The private pipeline builds Linux on its shared
runner. This workflow builds Windows x64, macOS arm64 and macOS x64 on standard
public GitHub runners, which GitHub documents as free and unlimited:
[runner reference](https://docs.github.com/en/actions/reference/runners/github-hosted-runners).

The workflow accepts only manual dispatches on this repository's `main` branch.
There are no pull request, push or fork build triggers. Give it:

- `source_sha`: the full lowercase commit SHA prepared by the private pipeline.
- `version`: the exact three-part release version in that commit's Cargo manifest.
- `request_id`: a new canonical UUID generated by that pipeline.

The private bridge temporarily stores its own read-only, repository-scoped
`GITHUB_TOKEN` as this repository's encrypted `CLIENT_SOURCE_TOKEN` secret.
`actions/checkout` receives that token only for the pinned private checkout, with
credential persistence disabled. The bridge job remains alive while native jobs
run, then deletes the public secret. Its token also expires when that private
job ends. No long-lived or broad private-repository access token is stored here.
The runtime revision comes from the pinned Cinnabar checkout in that source's
release workflow; update that single pin when changing the bundled runtime.

Private compiler/test/package output is redirected to a runner-local scratch log
and deleted after the build. Plaintext is never printed or uploaded publicly.
Failed stages print only a stage number and exit code. If configured with the
public `PRIVATE_DEBUG_PUBLIC_KEY` variable, the final 8 MiB of a failed log is
encrypted using RSA-OAEP SHA-256 and AES-256-GCM and uploaded as a separate
`native-debug-PLATFORM-ARCH` artifact. Only the private bridge receives the
matching `PRIVATE_DEBUG_PRIVATE_KEY` secret and can decrypt those diagnostics.
It verifies the failed run identity, artifact provenance/digest and authenticated
request context before writing private logs. Diagnostics also expire after three
days; the private source and plaintext logs never become public artifacts. Source checkouts, build trees and caches are never
artifacts; no build cache is enabled. Uploads contain only each platform's exact
compiled ZIP and SHA-256 checksum. The allowlist also rejects source files, logs
and archive traversal. Artifacts expire after three days. The private pipeline
adds its matching installers and publishes only after Linux and all three native
artifacts have passed verification.

## Private pipeline bridge

Use the private pipeline's `CLIENT_RELEASE_TOKEN` with public-repository Actions
write/read permissions to call:

`POST /repos/ZenoMCPE/images/actions/workflows/client-native-build.yml/dispatches`

Send `ref: main` and the three validated inputs. With the REST API header
`X-GitHub-Api-Version: 2026-03-10`, GitHub returns the exact `workflow_run_id`:
[dispatch API](https://docs.github.com/en/rest/actions/workflows#create-a-workflow-dispatch-event).
Record that ID and the public `main` commit at dispatch time. Poll that exact run,
requiring `event=workflow_dispatch`, `head_branch=main`, the recorded `head_sha`,
and `display_title=Native REQUEST_ID SOURCE_SHA VERSION`. Fail if it finishes with
anything except success. Never select a run merely because it is the latest.

Download by that exact run ID and accept exactly these artifact names:
`release-windows-x86_64`, `release-macos-arm64`, `release-macos-x86_64`. Each must
contain only the requested version's corresponding ZIP and `.zip.sha256` file.
Check both the GitHub artifact digest and the package checksum before combining
with the private pipeline's Linux archive. Publishing remains in the private
pipeline, so incomplete builds cannot publish a partial release.

Diagnostics use `cryptography==48.0.1`: its Windows amd64 and macOS universal2
ABI3 wheels support CPython 3.13 and both Mac architectures. Later 49/50 releases
removed Intel Mac wheels, so both builder and bridge deliberately share this pin.
[PyPI release files](https://pypi.org/project/cryptography/48.0.1/#files).
